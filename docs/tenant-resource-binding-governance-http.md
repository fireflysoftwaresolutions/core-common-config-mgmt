# Tenant resource binding governance HTTP

This optional owner boundary exposes the existing native maker/checker binding services. Enable both `firefly.configuration.tenant-resource-binding.enabled=true` and `firefly.configuration.tenant-resource-binding.governance-http-enabled=true` only after the separately governed native installation. Neither flag installs SQL, seeds a binding, changes default Flyway locations, creates a grant or permits a public route. The ordinary resource server, verified issuer/audience/JWKS, claim-only actor tenant and current strict PDP remain mandatory. Existing135 operations remain available unchanged.

The administrative platform actor tenant is the configured real Config platform UUID. The namespace being bound is a separate `(issuer, opaque platformTenant)` pair; its opaque value must never be parsed or copied as the resource UUID. Obtain the resource tenant and current eligibility from actual Config owner resources. The requested exact definition and generations remain part of every owner intent and native decision. A caller/body cannot provide its own STAFF identity or bypass independent-checker rules.

All three operations use POST with JSON under `/api/v1/tenant-resource-bindings/governance`, disable transport idempotency caching, and return `private, no-store` with `Vary: Authorization`:

| Path | Meaning |
| --- | --- |
| `/intents` | Read-only owner preparation of actionId and opaque intentDigest. No native proposal, reservation, lock or business grant. |
| `/actions` | Exactly one dispatch of the original typed owner intent and its original digest. |
| `/actions/observations` | Read-only historical observation of that original action, never a command/reconciliation. |

An `Intent` contains `kind` and exactly one typed branch: `preparation`, `decision` or `control`. Kind PREPARATION uses the existing Preparation/Command contract and creates the real native DRAFT proposal. Kind DECISION uses the existing DecisionCommand and its actual SUBMIT/APPROVE/REJECT/WITHDRAW transition. Kind CONTROL uses the existing Command and its ESTABLISH/REVOKE operation. These are binding-specific operations, not a generic saga or idempotency API. Inputs reject duplicate members, unknown nested fields, omitted required control expectations, scalar coercion, malformed UTF-8 and excess body bytes.

Retain the complete immutable request, actionId and owner-returned intentDigest before the first mutation. An ActionRequest contains the original Intent and originalIntentDigest. A changed request/digest is refused before dispatch. Every native effect still requires fresh current authorization, native eligibility/version checks and the existing audit/receipt transaction. The HTTP technical budget starts once before authentication, caps the entire attempt at five seconds using wall and monotonic time, and cannot renew on delayed subscription or reuse.

For an establishment, the real maker prepares the native DRAFT, submits its exact proposal, and a distinct authorized STAFF checker approves that exact target/version. Only then can a currently authorized executor establish the binding through the existing mapped owner control transaction. Retain each separate action and receipt. A failure after DRAFT/submission/approval does not erase the earlier committed state. Withdrawal/rejection/revocation are explicit supported owner transitions with their own current authority and original action, never invented automatic compensations.

An action result is COMMITTED with its matching native governance receipt or control completion, COMMITTED_RESPONSE_UNAVAILABLE when an observed owner commit is known but final authority/delivery is unavailable, or OUTCOME_UNKNOWN when no verified commit was observed. Both unavailable forms retain only the original action/digest and withhold the protected receipt. A known owner commit cannot be downgraded to uncertainty by late denial, stall or response deadline. After dispatch, a timeout, response loss, empty result or late authority failure cannot prove rollback. Never issue a replacement action or repeat a mutation automatically. Submit the same immutable ActionRequest to observations. A found result is a validated historical receipt and grants no current binding authority. NOT_OBSERVED_AT_THIS_READ is not proof of absence and does not authorize another write. INTENT_CONFLICT returns no other action receipt. Recovery requires fresh platform READ_ACTION PDP and the original full retained actor; expiry of the old business receipt window does not turn an immutable receipt into a new grant.

Recovery uses the existing native READ_ACTION context and Spring Data action/receipt repositories under the original factory transaction. It never invokes native prepare, decide, openControl, finishControl or reconcile. No new native SQL, history repair or provisioning grant is introduced here.

Source/controlled tests and generated SDK qualification do not establish actual Config Main governance, physical binding installation, signed Underwriter Main, real process-restart recovery or customer TERM_PC quote/bind/issue. Those remain separate executable acceptance gates. Generated Java must come from the unchanged original SDK generator and its exact same-invocation full138 producer; do not handwrite clients or substitute a cached JAR.
