# Tenant resource binding CURRENT HTTP

The opt-in production endpoint is `GET /api/v1/tenant-resource-bindings/current`. It accepts no request body or authority-selection query. The existing service derives the namespace from the trusted signed-token issuer and exact opaque `tenant_id`; clients do not submit a Configuration tenant UUID to discover their mapping. The mapped resource UUID is returned only by the actual current owner service.

Enable `firefly.configuration.tenant-resource-binding.enabled=true` only with the real binding native capabilities and the existing strict resource server. HTTP readiness requires the resource server enabled, explicit issuer/JWKS/audiences, strict policy, `tenant-required=true`, exactly `tenant-claim-paths=[tenant_id]`, and no public permit matcher covering this endpoint. Incompatible configuration refuses startup; settings are never rewritten. The genuine Firefly JWT converter projects signed claims only. A tenant header, default setting or missing/ambiguous signed claim cannot select a namespace. The existing security chain and all legacy routes remain unchanged.

One original wall/monotonic budget is captured per exchange before authentication. Delayed subscription and resubscription cannot renew it. The same object reaches `TenantResourceBindingService.current`. Owner observations may shorten the response deadline; their integral epoch-millisecond cutoff is charged against both wall and monotonic time without extending it. Expiry cancels downstream work and an uncommitted queued Current body is discarded through the actual WebFlux error path before a fixed sanitized 503 body is written. No guarantee is made about physical network completion or physical transaction commit after arbitrary waits. Successful and denied controller responses are not cacheable.

The response reuses the original Current records and codec. No independent native timestamp, namespace grant or authorization comes from ingress. Errors expose only fixed codes; authentication remains the existing bearer mechanism. Missing capability, empty output and unavailable/expired current authority refuse without a success fallback.

The metadata-only original OpenAPI application discovers this production controller using its existing framework mock-registration mechanism; this does not enable a business provider. New generated SDK Java and the canonical specification require a separate original Main/capture/Generator/package qualification. They are not authored by this source block.

Source tests use in-process controlled security/native collaborators. They do not prove actual JWT/JWKS, owner HTTP, SQL/native CURRENT, Ledger adoption, financial finality, raw-session/savepoint safety, physical commit deadlines or provider acceptance. The retained native327 CURRENT HTTP500/SQL55000 remains unresolved by these HTTP changes; its separate optional-V7 correction and actual runtime gate are required. The feature remains off by default and has no new mutation/control route.
