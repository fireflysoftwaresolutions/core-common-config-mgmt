# Optional native tenant resource binding

This directory is outside default Flyway and the separate document-issuer migration location. The feature remains off unless `firefly.configuration.tenant-resource-binding.enabled=true`. No existing POM, migration, canonical specification or SDK is changed. No HTTP/controller/scheduler mapping adoption is activated by this source.

The optional SQL is one atomic installation: exact original prerequisites and fresh namespace, two explicit closed metadata extensions, real mapped/private tables, canonical parsers and owning-context functions, explicit proposal/control/lookup/finish functions, policies/triggers/protected view, ownership/ACL attestation, then commit. It does not require functions before their tables. Re-execution or an existing partial namespace refuses and preserves existing objects. It has not been executed or native-qualified.

The Java implementation uses the actual SecurityContextPort and no-obligation current PolicyDecisionPort. Lookup preserves the exact verified issuer and opaque platform tenant String; it cannot reuse legacy UUID admission. Control-plane maker/checker/executor admission retains the existing canonical platform-tenant principal and UUID validation, with explicit binding action/resource kinds. The native repository is tied to the same named entity template as ordinary mapped persistence. The native adapter requires its actual owning transaction/factory and forwards actual current actor, original command and earliest absolute cap; it never returns a successful Java-issued grant/window/receipt.

READ_COMMITTED is explicit. Protected native context binds actual backend/XID, restricted effective role/session principal, isolation and read-write state, exact target/current eligibility, original command, before/after head plan and earliest finite cap. Local statement/lock timeouts and deferred final checks retain that cap; the same original monotonic Java budget covers policy, acquisition, calls and response. The COMMIT PDP recheck remains inside the same bounded owning transaction; ordinary never-returning-policy controls exercise controlled cancellation/rollback, while actual PostgreSQL lock/wait/session evidence requires its own future reviewed gate.

Native prepare/submission/independent approval/rejection/withdrawal uses the real common proposal/revision/control/decision lifecycle with explicit binding target/encoding additions. Old dispatchers, values and V5 bytes remain unchanged. Existing genuine tenant/status controls are required, never seeded. Native open proves exact approved original target and current epoch before ordinary Spring Data assigned immutable insert/full-head CAS. Native finish validates the actual effect and emits the real common action/receipt/audit/outbox with the real proposal/revision. A deferred final scope trigger requires the complete graph before marking its protected context completed. Completed context never authorizes another operation.

A private immutable definition anchor is captured only after actual creation action/receipt/audit/outbox exists. Its FK links, original maker/target/action/IDs/digest and original deadline are retained. Lookup and a new authorized revocation verify that immutable origin without equating a revocation maker to the original maker or manufacturing a UUID lookup actor. The anchor is historical origin evidence; it does not replace current PDP, head or eligibility authority. Fresh lookup observes current facts under its own original read budget and definition cutoff; it does not renew an old creation receipt.

Same-current-head duplicate execution can reuse a still-live original native receipt and preserved actors. Missing original anchors/receipts refuse. Historical command recovery after later head/eligibility changes is OPEN and needs a separate authenticated historical read contract. No business status is used to infer no-effect or successful native issuance.

All role memberships remain unchanged; only narrow new-object privileges are declared. No original audit-table RLS is widened for lookup. SQL source contracts and controlled driver tests are source evidence only. PostgreSQL session/ACL/DDL execution, real PDP/principal/provider acceptance, genuine OpenAPI/SDK emission for the new service, signed business HTTP, Ledger adoption, financial and release acceptance remain OPEN until separately qualified.

The completed witness is keyed by actual backend and full xid8. `current()` refuses completed rows. A second opener in the same transaction is refused even when constraints were forced IMMEDIATE and then DEFERRED. Only completed witnesses from an earlier XID on the same backend are purged; an unexpected older active row refuses. New transactions on a pooled connection can proceed. Completed markers may remain protected after commit until that backend next enters; active-context count and completed-marker retention are distinct.

This is the supported owning-service boundary, not a nontransactional lifetime-per-XID capability. The service forbids enclosing/nested transactions and exposes no savepoint operation. A raw session can roll back to a savepoint predating enter, rolling back the transactional witness too; raw-session/savepoint renewal remains OPEN. No GUC or advisory marker is treated as unforgeable authority.

Deferred constraint checks and application timers do not prove that physical commit/WAL completion occurs before an absolute deadline. Early constraint firing, later commit delay and uncertain client outcomes must not be classified as no-effect. Physical commit-deadline fencing and historical recovery remain OPEN, and this source does not authorize financial adoption.

It returns false for missing, expired, completed or non-lookup scope without fabricating a legacy context. Two guard-only UPDATE policies use that predicate with WITH CHECK(false); ordinary writes remain subject to the original legacy checks and mutable guards. No table privilege, runtime entry grant, seed or lock order changes. The installer attests the original SELECT/ALL policies plus these two exact lock-only policies and private helper ACL. All33 existing function bodies and V1-V5 remain byte-identical; one private function is added.
